01Approach

Unit Integration Manual
  • Three layers. Unit tests cover domain rules and handlers. Integration tests run the real app through WebApplicationFactory<Program>. The candidate runs the manual UAT against the live service at the end.
  • Traceability. Test method names start with the case ID, for example TC_U04_Duplicate_username_ignoring_case_throws_ConflictException. The "Traces to" column links each case to the spec section or decision it proves.
  • TDD order. Cases are implemented in the order listed: domain first, then handlers, then HTTP, then idempotency. Each one is written, seen failing, then made to pass.
  • No mocking framework. Handler tests use the real in-memory repositories and a hand-written stub for IUsersApi.
  • A few illustrative tests, not full coverage. Rule variations (several invalid usernames, say) are rows of one [Theory], not separate tests. That keeps the suite at 26 cases.

06Idempotency Integration

TC-I01 to TC-I04 go over HTTP. TC-I05 and TC-I06 test IdempotencyStore directly with a FakeTimeProvider, because "in progress" and "10 seconds later" can't be produced reliably over HTTP.

IDGiven / When / ThenTraces to
TC-I01When POST /users and POST /work-items are sent without the header, or with an empty one Then 400 "Idempotency-Key header is required." and nothing is created.Spec §08, Q9
TC-I02Given POST /work-items with key K returned 201 When the same request is sent again with K Then the status, body and headers are the same, the reply has Idempotent-Replayed: true, and GET /work-items?assigneeId= shows 1 item, not 2.Spec §08, Q9
TC-I03Given POST /users with key K returned 201 When K is sent with a different body, or to POST /work-items Then 422 "Idempotency-Key was already used with a different request."Spec §08
TC-I04Given POST /users {"username":"a"} with key K returned 400 When K is sent again with a valid username Then 201: a failed request releases its key.Spec §08, Q10
TC-I05Given key K is reserved and not completed When K is reserved again Then the store answers "in progress", which the pre-processor turns into 409.Spec §08
TC-I06Given key K completed at time T, with a 10-second window When K is reserved at T + 9s, then at T + 11s Then the first returns the stored response, the second is a new reservation, and expired keys are no longer stored.Spec §08, Q10

07Manual UAT Human gate

The candidate runs these against the live service (dotnet run) from requests.http, after all automated tests pass. Work is done only when every row passes. These check intent: that the API reads and behaves the way a client expects, not only that the code matches the tests.

08Not tested, on purpose

  • The generic 500 path. It would need a test-only endpoint that throws. UAT-10 checks that no internals leak.
  • Swagger output. Checked by eye in UAT-01.
  • Endpoint-to-command mapping in isolation. Endpoints are one line; the integration tests cover them.
  • Load and performance. Out of scope for an in-memory take-home.
  • Concurrent idempotent requests over HTTP. The atomic reservation is proven at store level (TC-I05) instead.
