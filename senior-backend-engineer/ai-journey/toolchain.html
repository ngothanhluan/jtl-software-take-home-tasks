03Research

  • context7 MCP server: current FastEndpoints docs on global pre/post processors, post-processors running when the handler throws, ProcessorState, and the Send methods. The idempotency design relies on these.
  • NuGet API: exact package versions and .NET 8 support, so the pinned versions in the plan were checked rather than remembered.
  • Web search: the FluentAssertions licence change and the alternatives (Q17), which led to Shouldly.

04Keeping the record

  • /export and /compact: the session outgrew the context window. Before compacting, the candidate exported it to transcript.md. Later parts go to transcript-part2.md so nothing is overwritten.
  • Decision log: each decision was added to decisions.html when it was made, quoting the candidate verbatim.

05Hooks and the environment

  • impeccable design hooks checked the HTML docs after each write. They flagged thick coloured side stripes, a heavy top border on the diagram cards, and all-caps body text. All were fixed in assets/style.css rather than suppressed.
  • oh-my-claudecode plugin kept recreating a .omc/ state folder. The candidate asked for it to be deleted, not git-ignored. So it is removed before every commit, and only explicit paths are staged.
  • Windows Smart App Control blocked the unsigned WorkTracker.Shared.dll during Task 2–3 test runs ("An Application Control policy has blocked this file"). The AI found the cause in the Code Integrity event log. A rebuild workaround proved unreliable. The candidate turned Smart App Control off, and tests have run natively since.
